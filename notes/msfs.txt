msfs native windows video fix

dxvk decodes video into a d3d11 texture and shares it to vkd3d d3d12
the texture metadata crossed only via the wine sharedgpuresource ioctl device
native windows has no such device so the import failed and video was audio only

fix
native fallback reads the metadata from a temp file keyed by the raw shared handle value
file name is tempdir then vkd3d-dxvk-shared then handle in hex then bin
struct dxvksharedtexturemetadata must stay identical in dxvk and vkd3d
both repos must use the same file name and the same struct or it breaks
also do not bail in opensharedhandle when the kmt to nt conversion is unavailable
keep the raw handle which imports via opaque win32 kmt

env free debug logging
msfs blocks env vars so we cannot set vkd3d debug or vkd3d log file
the launcher writes msfs-vulkan-debug.conf next to the game exe
it contains one line log_dir= then an absolute path
when present vkd3d forces full trace logging into log_dir then vkd3d.log
dxvk reads the same conf and writes log_dir then dxvk.log
launcher makes the dir as logs then unixtime

native shared resources for external apps
fenix a320 external app opens sim created shared textures with the real runtime
stock vkd3d exports vulkan opaque handles real d3d cannot open them
fix native_interop.c allocates shared textures through the real system32 d3d11
runtime and imports the memory into vulkan as d3d11 texture type
createsharedhandle then hands out the genuine runtime nt handle
foreign runtime handles are detected via d3dkmt query and imported the same way
dxvk side needs the symmetric fix for opening runtime handles still todo
